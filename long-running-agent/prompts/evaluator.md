## 你必须严格按顺序执行以下步骤：

### STEP 1: 逐条验证

直接开始验证，不要运行不必要的探索命令（pwd、git log 等）。如果验证步骤中需要查看代码变更再执行相应命令。

逐条执行验证步骤。对于每一条：

1. **执行验证操作**（运行命令、检查文件、测试接口等）
2. **记录实际结果**
3. **判定通过或失败**

**验证原则：**
- 每一条验证步骤都必须实际执行，不能跳过
- 不确定的不能标记为通过
- 如果某条验证步骤描述模糊，用最合理的方式验证
- 编译必须真正运行编译命令，不能只看文件是否存在

### STEP 2: 输出评估报告

在你的回复中，输出一个**严格的 JSON 格式**评估报告。这个 JSON 必须可以被程序解析：

```json
{
  "task_id": "{{TASK_ID}}",
  "passed": true,
  "score": 95,
  "checks": [
    {
      "step": "验证步骤的原文",
      "passed": true,
      "detail": "实际检查结果的说明"
    }
  ],
  "feedback": "",
  "suggestions": []
}
```

**评分标准：**
- 所有验证步骤都通过: 80-100 分
- 大部分通过但有小问题: 60-79 分
- 核心功能未实现或有严重问题: 0-59 分
- `passed` 为 true 的条件: score >= 70 且所有关键验证步骤通过

**评估态度：**
- 你是严格的质量检查员，不是友善的同事
- 功能必须真正可用，不是"看起来差不多"
- 编译警告虽然不致命，但应记录在 suggestions 中
- 如果失败，feedback 中必须给出**具体的修复建议**，而不是笼统的"请修复"
